RECOPILACIÓN DE REQUISITOS

Este campo asegura que el equipo del proyecto tenga un enfoque sistemático y planificado para identificar todos los requisitos relevantes del proyecto.

Métodos y técnicas de recopilación:

  • Entrevistas estructuradas: Con usuarios finales, gerentes de tienda, administradores
  • Talleres participativos (workshop): Sesiones colaborativas con equipos multifuncionales
  • Grupos focales: Con segmentos específicos de clientes objetivo
  • Cuestionarios: Para recopilar información masiva de usuarios potenciales
  • Observación: Análisis de comportamiento en tiendas virtuales existentes
  • Análisis de documentos: Revisión de procesos de negocio actuales
  • Benchmarking: Análisis de competidores y mejores prácticas
  • Prototipos: Para validar requisitos de interfaz de usuario

Aspectos que debe definir:

  • Qué técnicas específicas se utilizarán para cada tipo de interesado
  • Cuándo y con qué frecuencia se realizarán las actividades de recopilación
  • Quién será responsable de recopilar los requisitos
  • Cómo se documentarán los requisitos recopilados
  • Criterios para validar que los requisitos están completos y correctos

 

ANÁLISIS DE REQUISITOS

El "análisis" se centra en entender, evaluar y refinar los requisitos recopilados para que sean útiles para el proyecto.

Objetivos del análisis:

  • Transformar los requisitos "en bruto" en especificaciones claras y procesables
  • Identificar requisitos duplicados, contradictorios o innecesarios
  • Establecer relaciones y dependencias entre requisitos
  • Determinar la viabilidad de la ejecución del proyecto

Aspectos que debe definir:

  • Qué métodos de análisis se aplicarán a diferentes tipos de requisitos
  • Criterios para evaluar y priorizar requisitos
  • Proceso para identificar conflictos entre requisitos
  • Cómo se resolverán las inconsistencias o ambigüedades
  • Quién participará en el análisis y qué roles tendrán
  • Herramientas que se utilizarán para el análisis
  • Métricas para evaluar la calidad de los requisitos

 

CLASIFICACIÓN DE REQUISITOS

Define cómo se van a categorizar y organizar los requisitos del proyecto de manera sistemática.

Tipos de clasificación:

  • Por categoría funcional: requisitos del negocio, funcionales, técnicos, de calidad, de seguridad
  • Por prioridad: críticos, importantes, deseables (usando técnicas como MoSCoW: Must have, Should have, Could have, Won't have)
  • Por complejidad: simples, complejos, muy complejos

 

 

 

 

 

PRIORIZACIÓN DE REQUISITOS

Mientras que la "clasificación" organiza los requisitos en categorías, la "priorización" define cómo se van a ordenar y jerarquizar los requisitos según su importancia relativa para el éxito del proyecto.

Aspectos que debe definir:

  • Qué método de priorización se utilizará
  • Criterios específicos para determinar la prioridad (urgencia, dependencias, riesgo, ...)
  • Quiénes participarán en el proceso de priorización
  • Pesos relativos de diferentes criterios de priorización
  • Proceso para resolver conflictos entre interesados sobre prioridades
  • Frecuencia de revisión y actualización de prioridades
  • Documentación de la justificación para cada nivel de prioridad

 

MÉTRICAS DE REQUISITOS

Define cómo se van a medir y evaluar cuantitativamente los requisitos del proyecto para asegurar su cumplimiento y calidad. Las métricas transforman requisitos subjetivos en criterios objetivos y medibles, proporcionando una base para determinar si el proyecto ha tenido éxito.

Tipos de métricas:

  • Métricas de completitud: porcentaje de requisitos documentados vs. identificados
  • Métricas de calidad: requisitos bien formados, verificables, sin ambigüedades
  • Métricas de estabilidad: tasa de cambios en requisitos a lo largo del tiempo
  • Métricas de trazabilidad: porcentaje de requisitos vinculados a objetivos
  • Métricas de satisfacción: nivel de aprobación de los interesados
  • Métricas de cumplimiento: requisitos implementados vs. planificados

Aspectos que debe definir:

  • Indicadores específicos que se medirán para cada requisito
  • Criterios de aceptación cuantificables
  • Umbrales de rendimiento y rangos aceptables
  • Métodos de medición y herramientas a utilizar
  • Frecuencia de medición
  • Responsables de recopilar y analizar las métricas
  • Acciones correctivas cuando las métricas no se cumplan

 

VALIDACIÓN DE REQUISITOS

Define cómo se va a confirmar que los requisitos representan correctamente las necesidades de los interesados.

Aspectos que debe definir:

  • Métodos específicos de validación para cada tipo de requisito
  • Criterios de validación y estándares de aceptación
  • Quién participará en el proceso de validación (roles y responsabilidades)
  • Cuándo se realizará la validación (hitos, frecuencia)
  • Proceso para documentar resultados de validación
  • Manejo de requisitos no validados o rechazados
  • Herramientas y técnicas a utilizar
  • Proceso de aprobación final de requisitos validados

Diferencia clave con verificación:

  • Validación: "¿Estamos construyendo el producto correcto?" (requisitos vs. expectativas)
  • Verificación: "¿Estamos construyendo correctamente el producto?" (producto vs. requisitos)

 

 

 

 

TRAZABILIDAD DE REQUISITOS

Define cómo se van a establecer y mantener las relaciones entre los requisitos y otros elementos del proyecto a lo largo de todo su ciclo de vida.

Aspectos que debe definir:

  • Estructura de trazabilidad que se utilizará: Matriz de Trazabilidad
  • Herramientas para mantener la matriz de trazabilidad
  • Responsables de crear y actualizar la matriz
  • Proceso para establecer y verificar trazabilidad
  • Frecuencia de actualización de la matriz

Elementos típicamente trazados:

  • Objetivos ↔ Requisitos
  • Requisitos ↔ Casos de prueba
  • Requisitos ↔ Entregables del proyecto
  • Requisitos ↔ Riesgos identificados

 

DOCUMENTACIÓN DE REQUISITOS (REGISTRO DE REQUISITOS)

Elementos básicos que debe contener:

  • Identificador único para cada requisito
  • Título o descripción del requisito
  • Categoría del requisito
  • Prioridad asignada
  • Fuente u origen del requisito (interesado)
  • Criterios de aceptación

 

GESTIÓN DE LA CONFIGURACIÓN

Los requisitos se convierten en elementos de configuración una vez que son:

  • Documentados formalmente
  • Aprobados por los interesados
  • Establecidos como línea base (lñinea base del alcance)
  • Sujetos a control de cambios
